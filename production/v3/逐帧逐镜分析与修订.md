# 《蜀道难》逐镜修订 · 2026-10-29

参考为用户提供的 103.67 秒、30 fps 录屏。解码扫描全部 3110 帧，计算 3109 组相邻帧差异；关键动作与转场使用带源帧编号的连续接触表复核。扫描数据见 reference/every-frame.csv，接触表见同目录 JPG。这里区分自动逐帧扫描、抽帧目视复核和从视频推断的实现方式，不把它们混称为逐帧人工观看。

## 找到的突变原因

1. 原实现 `enter()` 在跨环境时直接重置相机、手、灯、星空与物件可见性，而背景另用 1.15 秒 CSS 过渡；多层时间不一致。
2. 前景透明度用阈值从 0 跳到 1，动作从固定值起步，不完全继承正在显示的姿态。
3. 迈步把相机高度立即写回固定数值；鸟起飞同时按帧和按时间累加，速度依赖刷新率。
4. 水流位移取模后周期性跳回；动作结束时统一清零晃动，可能截断尚未归零的运动。
5. 首次进入新景时编译着色器、创建渲染目标及上传纹理，导致一次性长帧。

## 实施

- 图片解码、各物件材质、离屏叠化通道在交互开始前预热。
- 摄影机、物件、人物前景、空气与文案使用同一 RAF 时钟，可一起暂停。
- 三维离屏画面与背景双层叠化；跨景继承旧景的完整可见状态。连续切章截取当前混合状态作为下一次转场起点。
- 使用起止速度和加速度均归零的五次缓动；动作分为准备、主体、收势、保持，结束时不强制归零尚有位移的通道。
- 同一场景仅更新文字，保持镜头及人物终态。跨景 0.68 秒，同景文字交接 0.38 秒。
- 手、灯的位移/旋转/透明度连续；鸟只按秒推进，起飞从零速过渡；移除水流周期性回跳。
- 第二轮录像发现半透明云雾在合成时出现亮度跳变，修正了线性色彩与预乘透明度的处理。
- 首次进入瀑布时仍有 SVG 滤镜计算长帧，已替换为提前准备的 GPU 水流片段着色器；透明画面混合通道也在开始前完成实际绘制。

## 对比验证记录

`continuity/` 保存同一组操作的旧版和修订版录像，以及逐 RAF 采样的镜头、手/灯姿态、转场进度和帧间隔。

首轮本机 Edge、1280×720 离线测试：旧版最长采样帧间隔 233.6 ms，修订版 33.4 ms；两版 95 分位均约 17.1 ms。修订版将首次准备工作移到可操作之前。此结果说明本机该组操作的长帧得到改善，不代表所有设备均锁定 60 fps，也不能替代画面复核。

后续色彩修复轮次发现了瀑布首次绘制 116.8 ms 的长帧，继续修复后，同一组操作的最终复测最长 50.0 ms、95 分位 16.9 ms，1991 次逐帧采样中只见一次超过 34 ms 的间隔，发生在开门。完整流程的最终实录另保存独立指标，避免把单次测试视为所有机器的表现。
