# 课件制作 GitHub 能力池

本池与InteractiveCourseware主Skill独立维护，目前只收录anatomy。池内保存入口、分析和证据，不内置整个上游仓库。版本规则为：录入时解析分类，选用前检查更新，制作时固定版本，使用后记录效果。

## 文件与使用

- `registry.json`：轻量索引，先读它再选择能力。
- `entries/<id>.json`：机器可检查的能力卡，具体字段以anatomy为样例。
- `entries/<id>.md`：详细阅读说明和适配建议。
- `scripts/pool.py`：Python 3.9+标准库工具，不需要额外安装依赖。
- `usage/<id>.jsonl`：发生真实使用后才建立的追加记录；不预造成功记录。

主Skill的`references/capability-pool.md`负责选择、解析及集成流程。脚本只负责确定性的校验、索引、版本和记录，不能根据网址自动判断教学适用性，也不会把外部Skill注册成当前平台工具。

在本目录执行：

```sh
python3 scripts/pool.py list
python3 scripts/pool.py validate
python3 scripts/pool.py check anatomy
python3 scripts/pool.py lock anatomy --project /绝对路径/某课件
```

`check`只读取GitHub公开提交信息，并更新本地上游观察记录；网络不可达、限流或返回无效提交时失败且保留原记录。再次检查可用ETag减少重复传输，不进行后台轮询。它不解析新版本文档，不把新提交直接标为已分析或已测试。

发现版本变化后，智能体应读取固定提交下的相关官方文件，更新能力卡的分析版本与适配结论，再执行`add`入库并`validate`。不因更新而自动升级在制课件。

```sh
python3 scripts/pool.py add /临时目录/能力卡.json --detail /临时目录/说明卡.md
python3 scripts/pool.py record anatomy --result /课件制作记录/能力使用结果.json
```

使用记录最少包含：

```json
{
  "project": "具体课件名",
  "commit_sha": "这里填写真实40位提交号，未知时改为null",
  "purpose": "本次实现的模块",
  "status": "tested",
  "checks": ["实际环境、操作、预期与结果"],
  "evidence": ["可定位的截图、测试记录或产物"],
  "limitations": ["尚未检查的范围"]
}
```

status可选`reference_only/generated/run/tested/delivered/failed`；未知版本须另写`version_note`，不能伪造SHA。`record`只追加使用历史，不自动提升当前上游版本的证据等级。条目JSON里的历史AED记录仅表示旧项目的经验，不表示新版anatomy已执行或已测试。历史项目证据不随能力池分发，路径以原工作区为基准；迁移后找不到原文件时只能使用已有记录摘要，不声称重新复核过这些证据。

`lock`记录写在项目的`.courseware-capabilities/`内，文件包含固定SHA及对应SKILL链接；不下载、不安装、不执行上游代码。默认要求分析版本与上游观察一致，选用前仍需先运行`check`。离线且已有可靠版本时，可显式用`--reviewed-version`锁定已分析版本，并如实说明本次无法确认更新。没有精确版本时不能锁定。项目已有不同版本锁时会拒绝覆盖，须先评估升级并保留旧锁。

## 扩充与迁移

以后录入新的GitHub链接时，智能体按主Skill规则检查真正入口、官方说明、示例、依赖和许可，写完整能力卡后入库。多个Skill入口分开记录；只有代码库或示例的项目应注明类型及适配工作。索引新增不需要把上游全文并入主Skill。

分发时保留本目录与`InteractiveCoursewareV1.2/`并列；若移动能力池，向智能体提供新的绝对路径或在当前任务记录中更新位置。主Skill独立安装而没有池时，不能声称已加载此池。

最终课件按运行约定带齐必要资源。此池、版本锁、制作记录留在课件运行ZIP之外；已交付课件不在运行时从GitHub获取更新。
