# 阶段二：完整视觉与场景定稿

读取已确认的功能表、体验与运行约定、素材身份及当前版本。视觉阶段呈现范围内的真实教学内容、场景和反馈，不用制作效果图新增未经授权的功能，也不编写整份生产课件。每张稿标注版本及对应功能编号；复合稿还要标出各区的状态。

## 先规划覆盖，再制作视觉

建立覆盖表，将每个功能和独立模块关联到状态、设计稿、素材及后续检查。先做一张样图可以探索风格，但样图通过只表示相应范围获得认可，不能当成整份课件已经定稿。风格探路属于阶段二内部工作或中途反馈，不另设必经用户确认点。

| 功能编号／独立模块 | 实际内容与关键状态 | 设计稿文件、版本 | 素材及取得状态 | 后续实现与验收 |
|---|---|---|---|---|
| F01／具体模块 | 本模块讲什么；操作如何改变画面；重要反馈 | 可实际查看的页面或状态稿 | 来源、用途；已取得／可复用／待生成／待程序实现 | 状态触发、视觉对应及可操作检查 |

覆盖规则：

- 全部独立模块都要有真实内容的代表界面，包含知识介绍、设备或对象探索、强交互及结果呈现等本次实际存在的部分。不能用主操作页代替其他模块，不能只交标题、空框或通用占位内容。
- 把影响理解、操作判断或结果解释的初始、操作中、错误、成功及完成状态列入表；按需要展示，不要求每个模块机械凑齐所有状态。视觉反馈与对应功能规则一致。
- 相同构图可共享样式说明，重复状态可以合理合并到一张分区稿或画册；每个独立模块的内容和重要状态仍须可逐项查看。注明复用关系，不以“布局一样”省略具有不同表达任务的模块。
- 数量按覆盖决定，不预设固定图数。完成条件是覆盖表没有未说明的空白，所有独立模块与关键状态都能定位到可审阅视觉。

## 产出可查看的实际设计

默认使用当前平台可用且适合本任务的高质量生图能力；不要求用户选择模型，也不为选型逐个试用所有模型。采用生图路径时必须实际生成并展示图像，提示词和待执行计划不算视觉结果。

设计必须遵循体验约定：默认单屏铺满浏览器视口，内容无需滚动获取；正文、操作目标与反馈在目标窗口内清楚可读。内容超量应分状态或步骤，不用无限拉长页面、截断正文或极小字号掩盖。不同窗口比例的重排规则应一并说明。

修正设计稿中的不可读文字、误画控件、科学错误及遗漏状态；必要时附准确文字或程序图层标注，不能把生图误差直接交给实现，也不能把效果图中的按钮称为已经可操作。

已有视觉、代码原型或用户免生图授权时复用有效材料并标明覆盖范围。缺少生图能力时，说明可提供的线框、程序绘图或可查看原型及差别，将替代路径与确认点 B 合并处理，不增加第三次默认确认。

## 将视觉参考与生产素材分开

| 类型 | 本阶段需明确的内容 |
|---|---|
| 视觉参考 | 用于确认构图、色彩、质感、空间和反馈；不能当成已可用的互动页面或三维模型。 |
| 实际素材 | 用途、来源、文件或待制作项、尺寸、格式、裁切／透明要求，以及人物、设备和环境的连续性。 |
| 程序绘制／模型 | 图层、几何、部件、材质、相机、热点与运动约束；哪些需要代码或模型实际实现。 |

阶段二完成生产素材规划，并验证影响成品效果的关键素材是否可取得、复用或制作。必要时对最难素材做最小取得或转换验证，避免仅凭漂亮效果图承诺可实现。完整素材制作与集成在阶段三落实；待生产项须有明确方式，不能把占位图默认为最终素材。

用户指定的原图或对象身份须跨稿一致。允许的裁切、投影、示意化或重绘按已确认约定执行；未经授权不能换成“相似”的设备或人物。程序控件与状态图层单独规划，不把整张效果图贴作假交互。

## 可实现的视觉交接

在设计稿旁保存精简实施约定，制作代理应能据此实现，而不需要重新发明布局：

| 项目 | 必须可定位的约定 |
|---|---|
| 构图与层级 | 主体区域及大致比例、留白、文字密度、前后层次、需要保留的视觉焦点。 |
| 字体与色彩 | 正文与标题层级、目标窗口中的可读大小、主要颜色、强调与反馈色；记录可复用样式。 |
| 素材身份 | 哪些是固定原图／角色／设备，哪些是示意；实际文件与参考稿分开编号或定位。 |
| 热点与反馈 | 热点所依附的对象、可点击／拖动范围、焦点提示、触发后变化，以及非拖拽替代操作。 |
| 状态与时序 | 状态名、进入条件、动作／语音／动画触发、暂停和结束行为；不同画面的对象位置及状态对应。 |
| 导航与适配 | 按已确认体验保留的控制、推进或回看入口，目标窗口范围、字幕／控件安全区及必要的重排规则。 |

空间交互还须明确默认与可变视角、部件关系、动作范围、参数与单位；不同视角、状态保持连接、数量与含义一致。真三维依赖的几何或模型、材质、相机与控制要另行交接，不能用一张效果图承诺已经可旋转、剖切或拆装。

标出不可随意变化的主要视觉特征与允许适配的部分。后续实际画面要按对应状态与定稿比较；未获授权不能因实现方便改掉主要构图、素材身份或交互位置。发现科学错误或实现冲突时修正相关材料，再同步下游，不为贴合效果图保留错误。

## 确认点 B 与阶段交接

展示完整覆盖的实际视觉和必要取舍，说明素材与程序实现的待完成部分，再请用户确认整套效果。仅确认过风格样图时，继续补齐其余模块后再完成这一次整套视觉确认；不要把样图确认升级为全模块授权。

已明确确认相同版本，或已授权按方案自动继续时，不重复询问。影响定稿的实质变更更新版本和差异；只有超出已有授权的取舍才按变更规则请用户选择。

交给阶段三：有效功能表、视觉覆盖表、实际设计稿、实施约定、素材清单与状态、事实边界及验收条件。由制作阶段落实素材，并按对应设计检查真实画面；设计阶段的漂亮图片和用户认可都不代替运行验收。
