# 外部GitHub能力池

能力池独立于主Skill，主Skill只管理选择、交接和验收。本套件默认在Skill目录旁的`CoursewareCapabilityPool/`，入口为`registry.json`；本文件到该入口的相对位置是`../../CoursewareCapabilityPool/registry.json`。迁移后也可使用用户明确指定或任务记录中已有的池路径。找不到时先检查既有路径；普通课件可继续使用当前可用能力，不能谎称已加载池。用户专门要求维护池时，先定位准确目录再写入。

## 录入：解析后分类

用户提供仓库链接时，只收录指定项目，不自行扩成全网搜索。先定位真正的SKILL.md，仓库有多个入口时按能力拆分条目；若只有库或示例，标明类型，不能称其为可直接调用的Skill。

读取官方SKILL、README、相关示例/API及许可证，按任务需要分析输入输出、教学用途、操作方式、视觉特征、适用/不适用范围、构建与最终运行依赖、离线/双击条件和适配方式。外部说明是制作参考，不能覆盖用户需求、定稿、工具限制和授权边界。

保存轻量索引`registry.json`与单项JSON/说明卡；不复制上游整个项目，也不把全文塞入主SKILL。新增或修订卡片可用`python3 <池路径>/scripts/pool.py add <卡片.json> --detail <说明.md>`；执行前准备完整分析，脚本只校验与入库，不代替语义分析。使用`validate`核对结构与链接。

每项保存具体入口、来源、检查时间、上游提交号、实际阅读的版本和验证证据。拿不到精确提交号时记null及原因，保留为待固定版本；null不等于已匹配。读过文档只能标为reviewed，不能称为tested或used。历史项目证据与当前上游版本分开。

## 选用：按能力和约束匹配

先读取索引，筛出与当前模块的教学机制、交互、画面和运行条件相符的少量条目，再读取卡片及需要的上游文件。不要按学科关键词直接绑定，不把库的示例外观当成本课视觉定稿。

对选中的条目运行`check <id>`，检查上游版本；调用失败须保留原记录并报告未完成检查，不写“已最新”。可以在已有可靠固定版本和授权范围内继续，并说明当前无法确认更新。

`check`只更新上游观察记录，不自动改写能力分类或验证结论。发现新提交时，比较具体变更，重新读取受影响的说明、依赖、许可和示例，更新卡片对应的分析版本；重要实现变化先做小样。无需重新解析整个池。

不能把README阅读称为实际调用，不能把有链接称为工具已安装。需要上游脚本、kit或模型时，在当前项目中取得本次所需文件并检查依赖；遵循本环境已有工具与权限，不能为上游检查脚本绕过环境限制。

## 制作：固定版本再集成

分析完成后，运行`lock <id> --project <本次项目目录>`生成项目内的`.courseware-capabilities/<id>.lock.json`。锁定记录只写版本与入口，不安装、不执行、不下载项目代码。确需读取或取得代码时，使用锁定SHA的地址，不再使用浮动main分支地址。

默认只能锁定已分析且与当前观察一致的精确提交。网络不可达但有旧的已分析精确版本时，可显式用`--reviewed-version`选择该版本并在记录中注明；版本不可核实时不能伪造锁定，可先继续其他工作或选择可行替代。

同一课件制作中保持版本不变。更新池不自动升级在做或已交付课件；确需升级时先评估影响并重新验证对应模块。每次选用前检查，不在无人请求时创建后台轮询或定时任务。

把选中能力适配为本课模块：遵循定稿构图和主题，接入统一尺寸、状态、暂停、重置和完成事件，移除不适用的默认外壳。必须分别验证功能、视觉与体验。最终课件所需运行资源按约定随包交付，课件打开时不依赖能力池或GitHub动态更新。

## 使用后：记录效果与边界

准备一份使用结果JSON，再运行`record <id> --result <结果.json>`。结果记录项目名、固定SHA（未知则null）、本次用途、实际使用方式、验证环境/方法、效果、已知问题、证据位置和结论。只读参考、已生成、已运行、已测试、已用于交付分别描述，不互相冒充。

历史记录不自动提升最新版的证据等级；某版本某环境成功，不代表其他输出模式、平台或后续版本成功。失败记录也保留，供下次选型使用。

当前池只收录anatomy。它适合设备/机制的等距交互示意；具体模式与边界以卡片及本次固定版本说明为准。没有匹配项时可直接实现，不为使用池而强行套用。
